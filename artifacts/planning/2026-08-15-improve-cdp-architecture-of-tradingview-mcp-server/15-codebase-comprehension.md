## Deep-Dive Sections

### CDP Transport — 2026-08-15

Traced the transport layer end-to-end against the prior research's R1–R5 breach map, using GitNexus flows plus direct reads at `4ff5104`.

1. **Shared client lifecycle** (`src/connection.js`): `getClient` liveness-probes the cached client with `Runtime.evaluate('1')` and falls into `connect()` (5-attempt exponential backoff, 500 ms base, 30 s cap). `reconnectTo(targetId)` closes and re-attaches — used by `tab_switch` and `attachChart`. Target discovery is three `/json/list` readers: `findChartTarget`, `findTargetById`, `findTargetByRef` (id → `/chart/<id>` segment → URL substring).
2. **Bypass sites and the wedge evidence**: `withTargetEvaluate` opens a private socket per background-tab read; its header comment records that TradingView's endpoint transiently closes fresh sockets when the shared dev-tools endpoint is busy, and the 4-retry + `TV_CDP_BUSY` (`retryable: true`) machinery is the mitigation. `capture.js` `_makeScopedClient` does the same for screenshots; `tab.js` opens three more for the Electron shell window (`app/window/index.html` — chart-page CDP cannot drive the Desktop tab bar; documented in the module header). Transient-tolerance (`isTransientCdpError`, backoff) exists **only** on the scoped path — the asymmetry confirms the wedge is a private-socket-vs-shared-client race, matching the 2026-08-14 parallel-tab contention incident.
3. **Page-path registry**: `KNOWN_PATHS` (11 paths) with `verifyAndReturn` existence checks. Consumers: data.js imports `CHART_API`/`BARS_PATH`; chart.js, stream.js (also `CWC`), study.js, indicators.js define identical local constants; pane.js, alerts.js, pine_ui.js, health.js (6 sites), wait.js inline the literals. Consolidation is mechanical — the strings are identical.
4. **Protocol-call scatter**: outside connection.js, raw CDP domains appear in dom.js (`Input.dispatch*`, payload builders), capture.js (`Page.captureScreenshot`), and the tab.js/capture.js client opens — each with its own error idiom. Everything else reaches CDP through `evaluate()`.
5. **Sleep duplication**: ~30 raw `new Promise(r => setTimeout(r, N))` sites across chart, tab, ui, data, pane, replay, pine, study, batch, drawing, stream — values 50–2000 ms, no shared helper; `wait.js` holds only chart-readiness polls.
6. **Health grab-bag**: exports `healthCheck`, `discover`, `uiState`, `launch`; privately `checkForUpdate` (git fetch + SHA compare, 1-hour cache) and MSIX copy/kill. Launch internals are DI'd (`_deps`) for tests. Splitting page-probe health from process-ops launch from git update-check is a pure move — no cross-calls between the three concerns observed.

Edge cases noted: `getLayoutNameForTarget` appears in the GitNexus index but not at `4ff5104` (index covers a slightly different revision — harmless for this pass). `isTransientCdpError` is exported but consumed only inside connection.js. The core public API (`core/index.js`) re-exports 12 namespaces; tab/stream/study/dom are absent from it though tools use them directly.

### Import Surface — 2026-08-15

Second-pass dive, run after the sufficiency gate resolved as dive-deeper. Traced every `from '../connection.js'` specifier and the wait/fetch helpers.

1. **Two import idioms.** Direct binding (`pine.js`, `stream.js`, `pane.js`, `indicators.js`, `alerts.js`, `ui.js`, `pine_ui.js`) versus aliased import plus a `_resolve(_deps)` seam (`chart.js`, `data.js`, `study.js`, `replay.js`, `watchlist.js`, `drawing.js`, `drawing_templates.js`, `batch.js`, `capture.js`, `health.js`, `dom.js`) where `deps?.evaluate || _evaluate` makes the transport injectable in tests. Consequence for the refactor: the DI-seam modules accept a new transport behind their existing seam with zero call-site edits; the direct-import modules are a mechanical sweep. Either way the public signatures (`evaluate`, `evaluateAsync`, `withTargetEvaluate`, getters) are the seam to preserve.
2. **Registry consumption has a second, working channel.** The verified getters — `getChartApi` (drawing.js), `getChartApi`/`getChartCollection` (batch.js), `getReplayApi` (replay.js) — already route through `KNOWN_PATHS` with existence checks. The first-pass "registry ignored" finding stands for the literal-binding modules, but the getter idiom is in-tree proof of the intended pattern, so consolidation extends an existing convention rather than inventing one.
3. **`/json/list` duplication.** Eight fetch sites: three in connection.js (the find* family) and five re-implemented in tab.js (list, withShell, isTargetVisible, newTab, closeTab/switchTab paths). tab.js reuses `CDP_HOST`/`CDP_PORT` from connection.js but not its finders — a `listTargets()` export would collapse the five copies.
4. **Waits: two generations coexist.** `wait.js` (`waitForChartReady`, `waitForChartRender`, DI-injectable evaluate) is the structured generation, adopted by batch.js, data.js, chart.js. The raw tail is 32 sites across 10 modules — tab.js 8, pine.js 5, chart.js 5, ui.js 3, pane.js 3, data.js 3, replay.js 2, batch.js 2, stream.js 1, drawing.js 1 — mostly guarding UI/render settling where a condition is hard to name. `dom.js` also exports a bare `sleep`. R4 is thus an adoption sweep onto existing helpers, with a per-site policy decision (bounded poll-or-timeout vs retained fixed delay) rather than per-site invention.
5. **CLI consumes beyond the public facade.** `src/cli/commands/` (15 modules) imports core directly, including tab, stream, pane, capture, and indicator commands reaching core modules that `core/index.js` does not re-export (tab, stream, study, dom, pane). The public API is a partial facade; the CLI's usage makes the missing namespaces de-facto public, which a transport refactor must treat as consumers.

## Challenge Lenses

### Pedagogy — 2026-08-15

Read the transport layer as a newcomer would. The survey holds up structurally — tools → core → connection is genuinely discoverable — but the teaching surface has three client idioms to explain (shared singleton, `withTargetEvaluate` scoped client, tab/capture private clients) where the design intent is one. The KNOWN_PATHS registry makes this worse pedagogically: a reader learns the registry pattern from connection.js, then finds it ignored in nine of ten consumer modules, and cannot tell which is the convention. These are comprehension debts, not correctness defects, and both are fixable without new concepts — a per-target pool behind the existing exports, and registry adoption by mechanical replacement.

### Rejected paths — 2026-08-15

Challenged the design as if defending the paths not taken. **Private clients everywhere** is refuted by the wedge evidence itself: the transient-close races appear precisely at the private-socket sites, while no contention has been observed on the shared singleton — the singleton is the load-bearing choice, not the mistake. **No registry (keep per-module literals)** fails the update-cost argument: ~15 identical literals across 10 files means a TradingView path change is a scattered edit with no verification, where `verifyAndReturn` already exists and fails with a named error. **Leave health.js whole as "operations"** survives naming review but fails cohesion measurement: the three concerns share no calls, so the split costs nothing but file moves. **Consolidate sleeps by inventing a helper** is wrong-footed — the helper exists (`sleep` in dom.js); the breach is adoption, not invention, which lowers the fix cost and raises the consistency argument for it.
